## 简报卡片跳转按钮 + 按钮状态修复

- 用户反馈：P1/P2 优先处理没有「打开消息」按钮；点击「完成/已处理」按钮状态没有变化。
- 根因 1：brief.py 的 `rank_priorities` 没有把 pending 项的 `link` 传给优先级；`_priority_blocks` 也没用 `link`，所以优先处理永远只渲染「完成」按钮。
- 根因 2：`extract_card_action` 期望事件里有 `open_message_id` 字段，但飞书 `card.action.trigger` 事件实际上没有这个字段；卡片的消息 id 就是事件顶层 `message_id`。
- 根因 3：serve 进程被多次重启后，留下的 card.action.trigger 消费者 pid 没被清理，新 serve 没接管；导致按钮点击事件被旧 serve 用旧代码处理。
- 修复：
  - `brief.py` 给 reply 候选注入 `link`；`rank_priorities` 透传 `link`；dedupe 后补回丢失的 link。
  - `brief_card.py` 的 `_priority_blocks` 把 `link` 传给 `_row_with_action`，渲染「打开消息」按钮。
  - `events.py` 的 `extract_card_action` 优先取 `open_message_id`，否则用事件顶层 `message_id`（即 card message id），保证 PATCH 时能找到原卡片。
  - `lark-cli event status` 找孤儿消费者，kill 旧 pid，重启 serve。
- 验证：27/27 brief tests 通过；`extract_card_action` 用真实事件测试得到正确的 `open_message_id`；新简报已推送。
