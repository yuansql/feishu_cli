## 简报消息状态判定漏掉第三方回应（已修复）
- 现象：简报「优先处理」里「P2 回复邱俊立：我喊上少华和梦晨一起 @周少华 @吴梦晨 已追问未答完」，但吴梦晨实际已回「ok」，却仍标未答完。
- 根因：`brief.py` 的 `mention_state()` 只调 `user_reply_texts(..., user_id=USER_OPEN_ID)`，**仅统计当前用户自己的回复**，完全不看群里其他人的回应。用户追问后状态为 `clarifying`（→「已追问未答完」），此后第三方回「ok」无人检测。
- 修改文件：
  - `partner/office/brief.py`：新增 `third_party_ack(messages, *, after, exclude_id)` —— 扫描非 USER_OPEN_ID 的消息，命中超短 ack（ok / 好的 / 收到 / 👍 / +1）或肯定短语（没问题 / 可以 / 同意 / 准时参加等，且不含疑问词）即返回 True；`mention_state()` 在 state == "clarifying" 时追加该检测，命中则升为 "answered"（→ 从简报过滤）。
  - `tests/test_brief.py`：新增 `ThirdPartyAckTests`（7 例），覆盖第三方 ok、带标点/emoji、肯定短语、仅自己发言不算、时间窗外忽略、问句不算、exclude_id 跳过原消息。
- 验证：`brief` 34/34 全绿；全量 395 tests，失败/错误数量与改动前基线完全一致（1 失败 `test_resolve_falls_back_to_inbox_without_brief` + 16 个网络错误，均既有、与本次无关——LedgerTests 设了 FEISHU_PARTNER_PENDING env，`ensure_pending_snapshot()` 提前 return，根本不 import brief.py）；smoke 23/23 路由 + 16/16 行为用例通过。
- 未装 LaunchAgent，无需 kickstart。

## 简报判定与账本进一步优化（同日完成）
- 在上午第三方回应修复基础上，继续完成 `/adhd` 收敛出的三条主优化 + 一条撤销通道：
  1. **参与者许可的 third_party_ack**：`brief.py` 的 `third_party_ack()` 增加 `participants` 参数；`_thread_participants()` 从原 @ 列表 + 线程内发言人构造许可集合；随机路人/ bot 的 "ok" 不再误关线程。
  2. **饱和/截断探测**：新增 `_fetch_group_mentions()` 替代 `_collect()` 中内联搜索，支持分页并返回 `(hits, truncated, fetch_failed)`；返回数据中加入 `truncated`/`fetch_failed`；`format_daily_brief()` 和 `brief_card()` 在文字/卡片简报顶部显式"⚠️ 可能漏采"横幅。
  3. **resolved 账本 TTL + epoch 租约**：`resolved.py` 增加 `LOGIC_EPOCH = 1`、`RESOLVE_TTL_DAYS = 14`；`is_resolved()` 改为租约检查（旧 epoch 或超 TTL 不再压制）；`mark_resolved()` 写 `decided_at` + `logic_epoch`；新增 `gc_resolved()` 物理清理过期行。
  4. **让「已解决」可质疑**：新增 `looks_like_unresolve()` / `unresolve()` / `unresolve_by_hint()`；`resolve_text()` 在销账前先识别"没解决/搞错了/撤销"等反悔语义，命中后从 ledger 删除对应行并重开。
- 修改文件：`partner/office/brief.py`、`partner/office/brief_card.py`、`partner/routing/resolved.py`、`tests/test_brief.py`、`tests/test_resolve.py`。

### 复用要点
- 判定「@ 是否已闭环」= 自己已回答 ∪ 自己追问后被许可的第三方 ack ∪ 发送方自我闭环。`participants` 集合是防止路人误关的最小护栏。
- 采集侧失败/截断不能沉默解释为"无待处理"；`_fetch_group_mentions` 返回状态旗并显式 banner。
- 本地 resolved ledger 应该是"可愈合的": 语义升级时 bump `LOGIC_EPOCH`、加 TTL、提供 `gc_resolved()` 清理过期误判。
- 撤销已处理是比"删错重来"更安全的 UX：把单向石碑改成可回滚账本。
